# Symphysis

Расширение VS Code для журнала решений symphysis: развилки, слово человека, внесение в журнал, схема решения и справка о шаге конвейера.

Расширение работает только в доверенной папке и только с локального диска.

## Хук для агента

Когда ты вносишь решение кнопкой или правишь `scheme.md`, агент должен об этом узнать. Для этого плагин сам ставит хук в проекте. Он ставится там, где есть папка `openspec`, инструменты symphysis и след клиента: папка `.claude` для Claude Code или `.opencode` (либо `opencode.json`) для opencode.

### Что плагин пишет в проекте

- `.claude/settings.local.json`: одну запись в `hooks.UserPromptSubmit`. Остальное в файле плагин не трогает. Если файл не разбирается как JSON, плагин его не меняет и говорит почему.
- `.opencode/plugins/symphysis-hook.js`: файл-обёртка для opencode. Первая строка файла помечает его как файл плагина. Чужой файл с таким именем плагин не заменяет.
- `.git/info/exclude`: строки с путями обоих файлов выше, в блоке между двумя комментариями `# symphysis-vscode`. Так в git они не попадают: в них записан путь к твоему Python. Если файл уже отслеживается git, плагин его не трогает.
- `.symphysis/viewer/`: скрипт `hook.py`, события просмотрщика `events.jsonl`, отметки прочитанного, черновики просмотрщика и `.gitignore` с одной строкой `*`. Каталог git не видит.

Для хука плагин больше нигде в проекте не пишет. Запись в журнал идёт только по кнопке «Внести»: в каталоге изменения появляется файл в `answers/`, меняется `decisions.json`, заново собираются `decisions.md` и `symphysis.html`.

### Настройка `symphysis.hook.enabled`

По умолчанию включена. Читается отдельно для каждой папки рабочей области, поэтому в одном проекте хук можно выключить, а в другом оставить. Если выключить, плагин снимет свои записи в проекте и больше не поставит их: запись в `.claude/settings.local.json`, файл `.opencode/plugins/symphysis-hook.js`, скрипт `.symphysis/viewer/hook.py` и свои строки в `.git/info/exclude`. События, отметки и `.gitignore` в `.symphysis/viewer/` остаются.

### Как убрать хук вручную

Так же делается после удаления плагина: при удалении плагин сам ничего не снимает, записи остаются в проектах.

1. В `.claude/settings.local.json` найди в `hooks.UserPromptSubmit` элемент, у которого во вложенном списке `hooks` есть обработчик с путём `/.symphysis/viewer/hook.py` в конце одного из `args`. Удали этот обработчик. Если в элементе больше ничего нет, удали элемент целиком; чужие обработчики в нём не трогай. Потом убери пустое: пустой `UserPromptSubmit`, затем пустой `hooks`. Если файл стал `{}`, удали и сам файл.
2. Удали файл `.opencode/plugins/symphysis-hook.js`, если его первая строка начинается с `// symphysis-vscode:`.
3. Удали каталог `.symphysis/viewer/`.
4. В `.git/info/exclude` удали блок от строки `# symphysis-vscode: файлы хука, строки до конца блока снимает плагин` до строки `# symphysis-vscode: конец блока`. Настоящий путь к файлу покажет `git rev-parse --git-path info/exclude`: в рабочем дереве git он общий для всех деревьев репозитория, поэтому снимай строки, только если хука нет ни в одном из них.

### Когда агент не услышит

Хук привязан к каталогу проекта. Если агент запущен в другом каталоге, чем тот, где лежит журнал, он записи не увидит и о решениях, внесённых кнопкой, не узнает. Запускай агента в корне проекта с журналом.

Хук доводит сообщение до модели, но модель может не принять его за служебное. На opencode с `deepseek-v4.1-flash` это случилось в 1 из 7 прогонов.

### Как обновить инструменты проекта

После обновления плагина инструменты внутри проекта остаются прежними. Обнови их из каталога установки symphysis:

```
symphysis install --project . --force
```
