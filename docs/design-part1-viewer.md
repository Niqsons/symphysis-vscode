# Symphysis VS Code, часть 1 — просмотрщик журнала решений

Дизайн первой части расширения: перенос в VS Code половины скилла
`symphysis-viewer`, обращённой к человеку. Собран из обсуждения
с владельцем 2026-10-31 — 2026-11-01. Решения владельца — с его словом
дословно и датой; решения исполнителя — отдельным разделом «проверь».
Заменяет для части 1 дизайн 2026-10-20 (локальный архив, в git не едет): тот писался
под другое ядро.

## Сводка

## Рамка

Расширение делается в три части; этот документ — только о первой.

1. **Просмотрщик журнала** — часть скилла `symphysis-viewer`.
2. **Интерактивная справка о ходе работы** — какой шаг выполняется,
   с какими артефактами и командами, подсказки, предыдущий и следующий
   шаг.
3. **Настройки symphysis** — все переключатели в расширении.

**Схема решения и справка о ходе работы — разные вещи.** Слово владельца
(2026-10-31): «схема в части два это справка о ходе работы. А схема
в symphysis-viewer и файле symphysis.html это динамически составляемая
схема по проектируемому решению».

Зачем расширение, если есть страница: VS Code открыт в том проекте,
с которым идёт работа; страницу не нужно открывать в отдельном окне
браузера и обновлять руками.

Скилл `symphysis-viewer` — две половины: инструкция агенту (когда
показывать, порядок `check → render → показ → apply`, главное правило
«вывод модели — развилка») и страница для человека. Расширение забирает
вторую половину и шаги «показать» и «внести» из первой. Главное правило —
дисциплина агента; расширение его не держит.

> То что плагин разойдется с шаблоном это хорошо. Если мы будем делать

Отвергнуто: показ страницы `render-html` в webview с прослойкой; подстановка

промпта расходится громко: `apply` — всё или ничего, отказ называет запись.

### Р19. Ядро без внешних пакетов — 2026-11-01

| Запуск | Итог |

Импорт стоит в начале модуля (`journal_model.py:11`), используется один раз
(`:257`), поэтому без пакета падает любая команда, даже `--help`. Пакет

`CLAUDE.md` symphysis: «под 3.14 нет пакетов, pip получает 403».

Выбран **вариант A**, сделано, коммит symphysis `9233146`: свой проверщик
подмножества JSON Schema, которым написан `journal.schema.json`, ~90 строк

до проверки. `jsonschema` остался только эталоном сверки в тестах
(`tests/test_journal_validator.py`). Проверено на Python 3.13 и 3.14.

Отвергнуто:

- необязательный импорт: пакета нет — проверка по схеме пропускается; битый
  журнал дошёл бы до просмотрщика;
- обязательный пакет: где pip получает 403, symphysis не работал бы;
- пакет в `.symphysis/` или venv: `jsonschema` тянет `rpds-py` — нативный
  модуль под версию Python; venv упирается в тот же 403.

### Р20. Агент узнаёт о правке схемы по хешу — 2026-11-01

> Хорошо, давай попробуем B. Если хук будет мешать кому то, то его легко убрать.

Пробный запуск (`docs/spike-part1-results.md`, раздел 4): через API различимо
«через редактор» и «мимо редактора», но не «человек» и «агент». Claude Code сам
вызывает `document.save()` при принятии diff и перед своим инструментом правки.
Поэтому Р16 снят: хук сверяет хеш `scheme.md` с тем, что видела эта сессия,
и печатает «`scheme.md` изменился с прошлого обращения». Первое обращение сессии
только запоминает хеш. Не зависит от редактора и от того, запущено ли расширение.
Ложное срабатывание — после собственной записи агента: лишняя строка в контексте
и перечитывание файла.

Отвергнуто: событие при сохранении в редакторе (срабатывает на принятый diff,
не видит правку в другом редакторе); без события.

### Р21. Три уровня цвета, настраиваемые; палитра Dracula — 2026-11-01

> Может цветовую раскладку сделаем конфигурируемой? Пускай пользователь указывает
> в какие цвета раскрашивать текст. Но ты прав, что нужно разделить на явно сигнальный
> цвет, на выделяющийся, и побочный, который надо выводить но не отвлекать. Возьмем
> палитру Dracula как в vs code theme.

| Уровень | Смысл | По умолчанию | Настройка |
| --- | --- | --- | --- |
| Сигнальный | надо реагировать | Red `#FF5555` | `symphysis.colors.signal` |
| Выделяющийся | важно заметить, не тревога | Orange `#FFB86C` | `symphysis.colors.accent` |
| Побочный | показать и не отвлекать | Comment `#6272A4` | `symphysis.colors.muted` |

**Раскладка исполнителя — проверь:**

- сигнальный: «цитаты нет дословно», блокер, понижение без причины, вердикт устарел,
  отказ `apply`, журнал изменён после показа;
- выделяющийся: открытая развилка, предупреждение, бейдж `deviation`, неснятая
  предпосылка, изменённый выбор, ссылка на несуществующий узел;
- побочный: «сверено», «корня для пути нет», «не проверить», справка, служебные метки.

Настройки — обычные настройки VS Code с выбором цвета (`format: color-hex`); страница
получает их переменными CSS и обновляется сразу. Это первые настройки, которые часть 3
покажет в своём интерфейсе. Контраст Comment на фоне Dracula около 3:1: годится для меток,
для длинного текста тускло, поэтому содержательный текст идёт цветом описания темы.

### Интерфейс

- **Боковая панель** — четыре списка:
  - изменения проекта (`openspec/changes/*`, кроме `archive`) со счётчиками:
    открыто, решено, статус атак;
  - поиск — фраза по всему журналу, строкам атаки и черновику, независимо от режима
    и фильтров; номер (`F-07`, `7`) показывает запись и её зависимости кратким списком;
  - оглавление журнала — для режимов «решения» и «проверка»;
  - оглавление атаки — файл → линза → строка; переход сам ставит режим «атака».
- **Вкладка просмотрщика** — три режима, как у страницы; выбранный режим и выбранный
  фильтр залиты цветом кнопки, фильтры стоят в шапке и не уезжают с прокруткой; Ctrl+F —
  окно поиска VS Code по тому, что сейчас на экране:
  - «решения» — варианты все, включая «маловероятно» с причиной;
    рекомендация под списком; антиподы; зависимости правит человек;
    добавленный вариант, новая развилка, парковка с адресатом, спор
    факта, замечания; бейдж `deviation`; фильтр: все, развилки, открытые, факты;
  - «проверка» — только чтение, «куда уйдёт» из `view-json`;
  - «атака» — группы линза → тяжесть, счётчики тяжести вне фильтра,
    «вне списка», понижение без причины, блок записи, спор строки.
- **Вкладка схемы** — `scheme.md` изменения, mermaid в строгом режиме
  (`securityLevel: 'strict'`); клик по узлу фильтрует карточки по полю
  `nodes`; запись со ссылкой на несуществующий узел — сигнал.
- Ширина — от ~760 пикселей: карточки в одну колонку.
- Цвета — три настраиваемых уровня (Р21).
- Схема: прокрутка и масштаб, «вписать по ширине»; брейншторм рисует сверху вниз (`TD`).

### «Внести»

1. Хеш `decisions.json` сверяется с показанным; расходится — журнал
   перечитывается, человек видит обновление до внесения.
2. Промпт сохраняется как есть в `answers/<дата>.md` (занято —
   `<дата>-2.md`, `-3`, …).
3. `apply`; отчёт `[ok]`/`[!!]` показывается дословно. Отказ — журнал
   не тронут, запись названа, человек правит выбор в интерфейсе.
4. `check`, `render-md`, `render-html`.
5. Событие в `.symphysis/viewer/events.jsonl`.

«Скопировать» остаётся — путь через агента в чате.

### Черновики

Состояние человека (выбор, слово, парковки, зависимости, добавленные
варианты, новые развилки, споры, замечания, споры по строкам атаки) —
в `.symphysis/viewer/<изменение>.json`. Внесённое в журнал из черновика
вычищается при каждом чтении журнала — как `cleanupIngested` шаблона.
Удобства — режим, фильтр линз, выбранное изменение, свёрнутость —
в `workspaceState`.

### Хук

Событие: изменение, файл ответа, хеш журнала до и после, отчёт `apply`.
Хук Claude Code `UserPromptSubmit` печатает непрочитанные события этой сессии
и строку о `scheme.md`, если его хеш изменился с прошлого обращения (Р20), —
вывод попадает в контекст агента. Курсор «прочитано» — свой у каждой сессии (номер сессии приходит
хуку на вход): с общим курсором первая сессия «съела» бы событие у второй.
Агент узнаёт о внесении тогда, когда к нему обращаются снова.

## Где может не сойтись

- **Два писателя журнала.** Агент прочитал журнал, человек внёс слово,
  агент записал свою копию — внесённое потеряно. Держат: сверка хеша
  перед «Внести», отказ инструментов Claude Code писать изменённый файл,
  строка SKILL «перечитай перед записью».
- **Черновики видит агент.** Невнесённый выбор, принятый за решение, —
  утечка того же класса, что держит главное правило. Держит строка SKILL:
  о слове человека агент узнаёт из чата или от хука.
- **Ссылка в никуда.** Человек переименовал узел — у записи `nodes`
  указывает на несуществующий; расширение показывает сигнал, `check` его
  не ловит (синтаксис mermaid понимает только JS).
