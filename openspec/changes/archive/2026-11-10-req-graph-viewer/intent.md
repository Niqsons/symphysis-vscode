## Критерии готовности

Ниже записан согласованный в этой сессии объём просмотра; формулировки сведены моделью по поручению владельца. Технические варианты реализации выбираются в журнале брейншторма.

- В плагине VS Code можно просмотреть req-graph активного изменения как Mermaid requirementDiagram.
- Можно открыть сохранённый req-graph.json, в том числе из архива; показ исторической структуры опирается на снимок.
- Основной сценарий — выбор части графа по capability или требованию; весь граф не показывается автоматически по умолчанию.
- Можно выбрать модуль по паре repo/module и увидеть требования, которые он реализует по явным связям implements, включая связи, полученные через файлы реализации.
- Требования, отобранные по модулю, показываются со связанными сценариями, задачами и решениями; другие модули их совместной реализации сохраняются как контекст.
- Выбор модуля можно сузить до capability.
- Диаграмму можно масштабировать, перемещать и вписывать в область просмотра; просмотр активного изменения поддерживает обновление.
- Отсутствие структурных данных в старом снимке явно обозначается; оно не выдаётся за подтверждённое отсутствие модулей.

Источник критериев: предложенный объём просмотра и дополнение о модулях в этой сессии; владелец уточнил смысл фильтра и ответил «Хорошо. Тогда можем начинать? стоит скорректировать intent из за модулей. и потом перейти к брейншторму», 2026-11-10.

## Границы

- Отдельный вид графа зависимостей модулей не входит в изменение: владелец выбрал сценарий «какие требования реализует модуль».
- Настройки интерфейса, способы получения и отбора графа, клики по узлам и граница доработок ядра обсуждаются в брейншторме; предложения модели в предыдущем исследовании сами по себе их не утверждают.
