# Proposal

## Why

Основание — F-17.A: человеку нужна визуальная проверка связей решений с требованиями и сценариями, включая отсутствие связей. Начальная точка просмотра и предварительный характер графа заданы F-14.A и F-15.A. Объём выбран в F-22.A, F-23.A и F-24.A.

## What Changes

- В плагине появляется отдельная вкладка req-graph рядом с журналом. У неё свои источник и фильтры; для рисунка используются Mermaid и существующие механизмы масштаба, перемещения и вписывания (F-01, F-07, F-10, F-22.A).
- Просмотр активного изменения доступен после формирования `specs`, включая период до появления замороженного файла; граф до заморозки обозначается как предварительный. Также можно открыть сохранённый `req-graph.json`, включая архивный, и показать историческую структуру по этому снимку (F-02, F-14.A, F-15.A). Наличие снимка само по себе не означает завершённости изменения (F-16).
- Основной сценарий — выбор части по capability или требованию. Добавляется выбор модуля по `repo/module`: он отбирает явно реализуемые модулем требования, включая реализацию через файлы. Выбор модуля можно сузить до capability; сценарии, задачи, решения и другие модули совместной реализации остаются контекстом выбранных требований (F-03–F-06).
- Ядро предоставляет публичный вывод для просмотра: один ответ содержит Mermaid-текст выбранной части и соответствие элементов рисунка исходным id и местам. Выбор живого источника или снимка и отбор по модулю выполняются на стороне ядра (F-23.A).
- Рядом с диаграммой показывается список записей и требований без найденных связей по данным сборки. Область списка — всё изменение или выбранная часть — явно обозначается; из списка можно выбрать объект для осмотра. Отсутствующие связи не дорисовываются, смысл решений автоматически не оценивается (F-17.A, F-24.A).
- Переходы по клику ведут к развилке в просмотрщике или артефакту в редакторе в пределах условия F-18.A: без сложной переделки графа и артефактов. Для связывания рисунка с источниками используется соответствие из ответа ядра; точность переходов должна быть проверена на закреплённой Mermaid (F-19, F-20, F-23.A).
- Отсутствие структурных данных в старом снимке явно обозначается и не выдаётся за подтверждённое отсутствие модулей (F-08).

## Capabilities

### New Capabilities

- `trace-graph-view`: публичный вывод ядра для просмотра живого графа или сохранённого снимка; выбор части по capability, требованию и модулю с сужением до capability; Mermaid-текст и соответствие элементов исходным узлам; данные для показа объектов без найденных связей и области их расчёта (F-02–F-06, F-08, F-23.A, F-24.A). Дельта: `specs/trace-graph-view/spec.md`.
- `plugin-trace-graph-view`: отдельная вкладка плагина, доступность после формирования `specs`, различение предварительного графа и снимка, управление источником и фильтрами, обновление, масштабирование, показ списка без найденных связей и выбор объекта для осмотра (F-01–F-08, F-14.A, F-15.A, F-22.A, F-24.A). Дельта: `specs/plugin-trace-graph-view/spec.md`.
- `plugin-trace-navigation`: переход из элемента диаграммы к записи журнала или исходному артефакту по соответствию из ответа ядра, в пределах условия о стоимости реализации кликов (F-18.A, F-19, F-20, F-23.A). Дельта: `specs/plugin-trace-navigation/spec.md`.

Вывод для просмотра отделён от интерфейса плагина, а переходы — от самого показа: их поведение можно менять независимо. Список без найденных связей относится к выбранному представлению графа и описывается вместе с ним (F-18.A, F-22.A–F-24.A).

### Modified Capabilities

Нет. Новый вывод для просмотра описывается capability `trace-graph-view`; требования существующего `trace-diagram` к `build --format mermaid` и `trace-snapshot` к заморозке не расширяются этим proposal. Основание такого разделения — добавление публичного вывода для просмотра в F-23.A.

## Impact

| Область | Что затрагивается | Основание |
| --- | --- | --- |
| Ядро symphysis, модуль `trace` | Выбор части графа, чтение источника для просмотра, генерация текста и соответствия элементов исходным узлам, данные об отсутствии связей | F-23.A, F-24.A |
| Плагин VS Code: новая панель и интеграция с `activation`, `core`, `protocol`, `ui` | Открытие вкладки, вызов ядра, передача данных странице, состояние источника и фильтров, управление рисунком | F-07, F-22.A, F-23.A |
| Плагин: `viewer`, `file-links`, переиспользуемые механизмы `scheme` | Переход к записи или файлу и управление Mermaid-рисунком | F-10, F-18.A, F-19, F-22.A |
| Граница ядро — плагин | Публичный ответ для просмотра, содержащий текст диаграммы и соответствие исходным узлам; конкретная команда и форма полей относятся к последующему проектированию | F-23.A |
| Сохранённые данные | Историческая структура читается из снимка; ради кликов форматы графов и исходных артефактов не меняются | F-02, F-08, F-23.A |

Планирование ведётся в этом изменении плагина; участвующий внешний repo ядра указан в `.openspec.yaml`. Изменения кода ядра и плагина следуют одной выбранной границе: ядро готовит выбранный вид, плагин показывает его и выполняет переходы (F-23.A).

Для показа используется уже применяемый в плагине Mermaid-рендерер (F-10, F-22.A). Возможность точного связывания его SVG с данными ответа проверяется при реализации; условие F-18.A сохраняется (F-23.A).
